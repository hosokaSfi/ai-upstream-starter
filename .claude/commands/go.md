プロジェクトの現在地を判定し、次にやるべきことを実行してください。補足: $ARGUMENTS

## 判定と行動(上から順に評価、最初に該当したものを実行)

1. **中断がある** — `python3 tools/pipeline.py status` で in_progress の工程と
   docs/wip/ の継続メモがある → /resume と同じ手順で途中から再開する
2. **何もない(初回)** — docs/ にドキュメントがない → インプット(ストーリー・メモ)の場所を
   聞き、requirements-definition スキル(要件定義)から開始する
3. **承認待ちがある** — 直前の工程の成果物がドラフトのまま → 機械チェック(/check相当)を
   実行してから「どこを見て承認すべきか」を3行で提示し、**停止する**。
   承認されたら(「OK」「承認」等)ステータスを承認済みに更新して次の工程へ
4. **次の工程が明確** — 承認済みの成果物が揃っている → パイプライン順
   (req → design → db/arch → backlog → release → sprint)の次の工程のスキルを実行する
5. **全工程完了** — `python3 tools/check_gate.py` で最終ゲート判定を出し、
   人間チェック項目のリストを提示して完了を宣言する

## 「全部」モード

引数に「全部」「一気に」が含まれる場合のみ、承認ゲートで停止せず最後まで連続生成する。
その場合は全成果物の管理ヘッダに【未承認ドラフト】と明記し、最後に
「承認が必要なドキュメント一覧と、見るべきポイント」をまとめて提示する。

## 常に守ること

- 各工程の実行内容は該当スキルの手順に完全に従う(委任・ロジック委譲・チェックポイント含む)
- 応答の冒頭に必ず「現在地: ○○ / これからやること: ○○」を1行で示す
- 応答の最後に必ず「次のアクション: (あなたがやること1つ + 次も `/go` でよい旨)」を示す
- 仕様変更の相談が混ざっていたら /change の手順(変更提案書)に誘導する

要するに: ユーザーは何も覚えなくてよい。「/go → 質問に答える/承認する → また /go」の
繰り返しだけで上流工程が最後まで完了する。
