# Definition of Ready / Definition of Done

<!-- チームの作業合意。スプリント計画・レビューのたびに参照する。
     変更はレトロスペクティブでチーム合意のうえ改訂する。 -->

## Definition of Ready(スプリントに入れてよいストーリーの条件)

- [ ] ユーザーストーリー形式で書かれ、価値(なぜ)が明確
- [ ] 受入条件がGiven/When/Then形式で3個以上ある(異常系を含む)
- [ ] SPがチームのポーカーで見積り済み(8SP以下)
- [ ] 依存する設計が存在する(画面項目・API・テーブルが設計書で参照できる、
      または【リファインメントで詳細化】の範囲が合意されている)
- [ ] 依存ストーリー・外部依存(他社API仕様等)が解決済みか、期限つきで管理されている
- [ ] デモ方法がイメージできる(レビューで何を見せるか)

## Definition of Done(ストーリーを完了と呼べる条件)

- [ ] 受入条件をすべて満たし、自動テストが受入条件をカバーしている
- [ ] コードレビュー承認済み(1名以上、自己レビュー不可)
- [ ] CIがグリーン(lint / unit / 結合)
- [ ] 設計書との乖離がない(実装で設計を変えた場合、設計書を改訂済み)
- [ ] ステージング環境にデプロイされ、動作確認済み
- [ ] 重大バグ(Critical/High)が残っていない
- [ ] POがスプリントレビューで受け入れた

## スプリントのDoD(リリース判定に使う追加条件)

- [ ] リリースノート・ユーザー告知文の更新
- [ ] マイグレーションのロールバック手順確認
- [ ] 監視アラートの誤検知がない状態で24時間経過(本番リリース時)
